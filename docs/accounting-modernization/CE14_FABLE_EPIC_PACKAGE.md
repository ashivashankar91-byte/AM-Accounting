## EPIC OBJECTIVE & BUSINESS PROBLEM
The dealership's relationship with its manufacturer runs through money: factory receivables (warranty, incentives, holdback, co-op), factory statements that must be matched to the dealership's own books, and the monthly OEM financial statement the dealer principal signs. Today that is manual, error-prone, and audit-exposed. Outcome: factory paper becomes governed evidence — ingested or entered truthfully, matched deliberately, posted through the engine, reserved where the factory can claw back, and rendered into the OEM financial statement from the same ledger that produced the trial balance. **No fabricated factory acknowledgment, ever.**

## THE OEM BOUNDARY (governs the whole epic)
Live OEM connectivity (credentials, endpoints, certification, statement-spec versions) is **external truth this package does not claim**. Every OEM-facing capability ships as: adapter contract + deterministic labeled fixtures + implementable manual/import fallback + truthful status enum `NOT_CONFIGURED · TEST_ONLY · CERTIFICATION_PENDING · CERTIFIED` (CERTIFIED settable only with recorded certification evidence reference — no code path flips it silently). Transmission-style operations (submission, RDR, claim filing) are **prepare/export/record-response** in Pass-1: the system prepares and exports artifacts and records externally-obtained responses as entered evidence; it never simulates a factory response. Statement-spec content (factory account layouts, page/line definitions) is **versioned configuration/profile data sourced from OEM documentation — never invented line mappings**; absent profile content ⇒ the surface states it truthfully and blocks rendering rather than approximating.

## STORY CONTRACTS

**S098 OEM Adapter Framework & Diff Alerts.** Persona: Controller/Admin + Accounting. The framework story: OEM profile model (make, program ids, dealer codes per store, statement-spec version refs, connection status enum above), adapter SPI (feed pull/file import → staged documents), staging store (immutable raw + parsed rows, import audit, dedupe on document identity), **diff alerts**: when a re-delivered/updated factory document differs from its staged predecessor (amounts, line counts, spec version), a named diff alert raises with field-level comparison — factory data changing under you is a signal, never silently overwritten. Manual import always available and labeled. AC: staged docs immutable + deduped; re-delivery diff alert with field diffs; status enum truthful (fixture CERTIFIED requires evidence ref); nothing posts from staging without a downstream story's ceremony.

**S099 Ford Feed Adapter / S100 GM Feed Adapter.** Persona: Accounting. Concrete adapters on the S098 SPI for the two Pass-1 makes: parse the make's statement/remittance feed formats (spec versions = profile config; parser tolerant-strict: unknown segment ⇒ staged with UNPARSED flag, never dropped or guessed), map parsed rows to canonical staged-document types (receivable remittance, chargeback notice, incentive statement, parts-return credit, co-op statement) for S101A/S103A/S105/S106 consumption. Fixtures per make; `TEST_ONLY` until certification evidence recorded. AC per adapter: fixture feeds parse to canonical rows byte-accountably (every input row staged, parsed or UNPARSED — zero silent loss); spec-version mismatch raises diff alert; no posting from the adapter itself.

**S101A Manual OEM Statement Match Workbench.** Persona: office manager/accounting. The heart of Pass-1: match staged factory rows (fed or manually entered — full manual grid for makes with no adapter) against the dealership's open factory items (CE-11 S065 warranty claims, S071 parts returns, S103A incentive accruals, S106 co-op claims — via CE-08 item queries [PUTR: item-type filters]). Match ceremonies: exact match → remittance application (posts via CE-09 receipt path, applyNumber=claim/incentive ref [PUTR: receipt linkage]); short-pay → disposition per the approved S065/S049 pattern (write-down per matrix rows, or transfer-to-dispute item); factory-not-on-our-books row → investigation worklist; ours-not-on-statement → aging continues, exception per config. Match sessions: scoped per statement document, completable only when every row dispositioned (matched/short-paid/disputed/investigated) — no silent leftovers. AC: session completion requires 100% row disposition; applications relieve items exactly; short-pay conserves; every disposition audited; manual-entry statement fully equivalent to fed one.

**S103A Incentive Registry & Flat RDR Accruals.** Persona: accounting + sales admin. Incentive program registry (program id, make, terms summary, flat per-unit amounts or entered rate tables — program CONTENT is factory-published configuration, never invented), RDR-linked accrual: on delivery-reported events (deal delivered w/ RDR data from CE-12 recap [PUTR: rebate/incentive fields on deal.finalized]) accrue receivable per registered flat program (DR factory incentive receivable item, applyNumber=deal#+program / CR incentive income or vehicle-cost offset per matrix-row structure) — **flat programs only in Pass-1; experience/volume-tiered estimates excluded** (recorded: tiered accruals need attainment data → CE-17/Pass-2 or entered-evidence adjustments). Factory incentive statement rows match in S101A. True-up: entered factory statement figures adjust accrual via ceremony. AC: accrual = registered flat amount × qualifying fixture deliveries exactly; unregistered program ⇒ no accrual + visibility flag; true-up ceremony conserves; receivable tie: GL = Σ open incentive items.

**S104 OEM Financial Statement Renderer.** Persona: Controller/dealer principal. Renders the make's financial statement from the SAME ledger truth as the trial balance: statement profile = versioned page/line/column definitions + **account-mapping profile (dealership GL accounts → factory statement lines) = Accounting-authored configuration under standing governance (authored, versioned, activated author≠activator, blank until authored — the S009 metadata foundation extends here [PUTR: S009 admin surface])**; render = as-of-period computation with drill from any statement cell to contributing accounts/journals; validation panel: statement-internal cross-foots + statement-total-vs-TB tie (a statement that doesn't tie renders with a LOUD variance banner, never silently balances); memo/statistical lines (counts, units) source from operational feeds as entered/derived evidence with source labels. Export: spec-version-stamped file per profile (format per factory spec config); **submission = export + recorded-response in Pass-1** (transmission adapters are S102). AC: fixture profile renders byte-stable; every cell drills; TB tie proven + injected variance loud; absent profile content blocks with truthful message; export stamped + retained + audited.

**S105 Warranty Audit Chargeback & Reserve.** Persona: Controller/warranty admin. Factory warranty audits claw back paid claims: chargeback notice (staged doc or entered) → assessment workbench (affected claims list, dispute vs accept per line) → accepted ⇒ chargeback posting (CR warranty receivable/claim history → DR chargeback expense or reserve draw per matrix rows) with claim lineage to the ORIGINAL S065 items (already-relieved claims charge back via new payable/contra item — never mutate applied history, standing conservation boundary) → disputed ⇒ dispute item + evidence pack (claim docs refs) → **audit reserve**: configured-rate accrual against paid warranty volume [rate = tenant config from experience; preview-approve periodic posting; no invented actuarial model], draws on accepted chargebacks, excess to expense. AC: accepted chargeback conserves with full lineage; dispute path posts nothing until resolved; reserve = approved previews Σ − draws; reserve never goes debit (guard); already-relieved clawback creates the contra item exactly.

**S106 Co-op Advertising Claims.** Persona: office/marketing admin + accounting. Co-op program registry (make program, accrual basis: % of qualifying vehicle sales or entered program terms — config), claim preparation: qualifying spend items (entered/imported invoices w/ evidence refs from CE-09 AP linkage [PUTR: AP doc reference]) → claim package export → factory response ENTERED (approved/denied/partial per line) → approved ⇒ receivable item → statement rows match in S101A → denied ⇒ write-off ceremony per standing threshold config. Accrual option: periodic co-op accrual per basis config, preview-approve, trued to claims. AC: claim package totals = selected spend exactly; response entry drives item creation per line; denial write-off conserves; accrual = approved preview; no fabricated response path exists.
