**Canonical membership (frozen, registry-reconciled, 4):** S129 Item-Level Schedule Migration & Gates · S130 TB Conversion & COA Mapping Workbench · S131 Parallel-Run Comparison Harness · S132 Statement Archive Import & Runbooks — all R6. ## OBJECTIVE & BUSINESS PROBLEM
A dealership cannot re-key its books. Conversion off legacy AutoMate (and, by the same machinery, off competitors — the strategic plug-and-play thesis) must move the trial balance, the open schedules, and the statement history into the modern platform with **proof**: control totals, debit/credit conservation, row-level lineage, rehearsals before cutover, a parallel run that explains every difference, and a rollback that actually works. Migration is a governed, repeatable, evidenced process — never a script someone ran once.

## GLOBAL RULES
Standing discipline incorporated by reference (CE-09..CE-15 packages): additive committed migrations only (no db push, no editing historical migrations), tenant+LE isolation, RLS pos/neg non-superuser, immutable audit, permissions manifest→S207 (migration.* tier, distinct from accounting.*), unified-shell UI from the committed Claude Design source, server-side computation, standard states everywhere. **Migration-specific law:** loaded financial data enters the modern ledger THROUGH the governed path — conversion journals/opening balances post via CE-07 engine events (migration event family; matrix rows blank per standing rule; labeled fixtures) — no side-door table loads into GL/schedule tables in certified runs [the loader writes staging; promotion posts]. **Do not invent legacy field meanings:** every source field's meaning comes from the mapping workbench (human-confirmed mapping decisions with provenance — the System-DNA/crosswalk evidence is input, a person confirms); ambiguous/invalid/unmapped values NEVER coerce — they enter the exception queue. Sensitive data masked in non-production; production-shaped fixtures for certification are synthetic. **No migration directly into production without certification gates** (gate model below). External truth (legacy extract access, credentials, source snapshots) = boundary: `SOURCE_NOT_CONFIGURED` truthful; fixture extracts for certification.

## RUN MODEL (authoritative, all stories)
Migration RUN = immutable identity (runId, tenant, entity scope, source snapshot ref, transformation version, mode: REHEARSAL | PARALLEL | CUTOVER) with state machine per dataset: `DISCOVERED → MAPPED → STAGED → VALIDATED → RECONCILED → READY_FOR_CUTOVER → CUTOVER_IN_PROGRESS → CUTOVER_COMPLETE` + `ROLLED_BACK` + `MANUAL_REVIEW_REQUIRED` (exception-queue datasets). Runs are repeatable/restartable: idempotent reruns keyed (runId + dataset + source row identity) — a rerun never double-loads (load ledger with source-row hashes; duplicate detection at staging); transformation logic versioned and pinned per run (same input + same version ⇒ same output, property-tested); every rejected row retained with reason evidence; control totals captured at extract, staging, transform, and load; **freeze window** discipline: cutover mode requires declared source freeze attestation + delta-migration pass (changes since snapshot) before completion; rollback = governed reversal of the run's promotions (posted conversion journals reverse via S218 lineage; staged data flagged ROLLED_BACK, never deleted) + restart capability. Cutover approval = ceremony with dual SoD (migration operator ≠ cutover approver; irreversible-step confirmation states exactly what cannot be undone) [migration authority = the one genuinely irreversible domain: gate it hard].

## STORY CONTRACTS

**S130 TB Conversion & COA Mapping Workbench.** Persona: conversion specialist + dealership Controller. The mapping heart: source inventory (legacy COA, departments, entities/rooftops → tenant/LE/store mapping, statement metadata), **COA mapping workbench** — source account → target account decisions with align/map/diverge classification (the crosswalk made operational), department/dimension conversion rules, per-mapping provenance (who decided, basis evidence link), versioned mapping sets (immutable once used by a run), coverage meter (unmapped source accounts named — 100% disposition required: mapped, merged-with-note, or explicitly excluded-with-reason before VALIDATED). **TB conversion:** per period in scope — source TB extract (adapter/file; truthful states) → transform per mapping version → staged converted TB → validation (per-account and total debit/credit conservation: source Σ = converted Σ exactly; per-entity integrity) → promotion posts opening/comparative balances through the engine (conversion journal family), lineage from every posted line to source rows. Beginning balances + comparative history periods per scope config. AC: conservation exact on fixtures (property: any mapping permutation conserves totals); unmapped account blocks validation naming it; mapping-version pin proven (rerun same version = identical output); promoted TB = staged TB; lineage drill source→journal works; closed-period history loads as history (no reopening of modern periods).

**S129 Item-Level Schedule Migration & Gates.** Persona: conversion specialist + staff accountant. Open-item conversion for controlled accounts: source open AP/AR/schedules extract → per-item transform (control/apply/reference semantics mapped to the approved UQ-18 fields — mapping decisions in the workbench, never guessed) → staged items → **gates** (the story's named concept): G1 item-level validity (required references present or excepted), G2 subledger conservation (Σ staged items per account = converted TB control balance from S130 — the cross-story tie), G3 duplicate/identity (no double-load; source identity hashes), G4 aging integrity (item dates map; aging basis preserved), G5 exception-queue zero-or-dispositioned. Promotion creates modern CE-08 items via the governed path (migration item-establishment events) with source lineage. Bank/reconciliation data: open outstanding checks/deposits stage as reconciliation-carry items feeding S054A's outstanding lists [PUTR: CE-09 final rec model]; vehicle/fixed-ops/payroll/OEM balance datasets ride the same gate machinery where in scope (balances + open items; operational history beyond accounting scope = excluded, recorded). AC: every gate demonstrably blocks on its fixture violation; G2 tie exact; promoted items = staged items with lineage; rerun idempotent; exceptions dispositioned or run stays MANUAL_REVIEW_REQUIRED.

**S131 Parallel-Run Comparison Harness.** Persona: conversion lead + Controller. The proof engine for the parallel month: while legacy and modern both run, ingest legacy-side period outputs (TB, schedule balances, statement figures — extract/file, truthful states) and compare against modern equivalents: comparison sets (account-level TB diff, schedule control diffs, statement-line diffs via mapping version), **every difference classified** (timing / mapping / legacy-error / modern-error / unexplained) through a disposition workflow — **the exit criterion is 100% of differences explained and dispositioned, not zero differences**; unexplained differences block cutover recommendation. Comparison runs versioned + immutable; trend view across parallel periods; sign-off ceremony (Controller) per period's comparison. AC: diff computation exact on fixtures; classification workflow enforced (no bulk-dismiss without reason); unexplained>0 ⇒ READY_FOR_CUTOVER refused; sign-off SoD (operator ≠ signer); evidence retained.

**S132 Statement Archive Import & Runbooks.** Persona: conversion specialist + Controller + support. Two halves per the accepted title: **(a) Statement archive import** — legacy issued financial statements (monthly OEM/management statements, closed-year packages) import as immutable archived artifacts (files + index metadata: period, entity, statement type, source), retained under S017 WORM classes, searchable/viewable beside modern statements for continuity (comparative reference, audit support) — archived artifacts are EVIDENCE, never re-computed or edited. **(b) Runbooks** — the operational discipline productized: per-migration runbook instances from templates (discovery → mapping → rehearsal(s) → parallel → freeze → delta → cutover → post-cutover support checklist), each step with owner, status, evidence link, and gate linkage (steps auto-tie to run/gate states — a runbook cannot show cutover-approved while gates are red); post-cutover support log (issues, resolutions, delta corrections). AC: archive import immutable + indexed + retention-classed; runbook step states derive from real gate/run states (no manual green-washing); template versioning; cutover step requires the dual-SoD ceremony evidence.
