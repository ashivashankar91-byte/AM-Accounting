## Criteria

**AC-1 — Golden posting.** *(Bucket B — blocked)* Given an ACTIVE approved mapping matrix version vX containing an approved entry for event E with an Accounting-authored expected journal, When E arrives in a valid SourceEventEnvelope, Then exactly one balanced journal posts via S019/S020/S013, matching the golden byte-exactly, pinned to vX, with source-document linkage. *Executable only after `ACCOUNT_MAPPING_VALUES_PENDING` clears — golden values are Accounting-authored, never engineering-invented.*

**AC-2 — Deterministic ambiguity.** *(Bucket A — ready)* Given two equally valid rules/packs for an event, Then the event rejects with the distinct ambiguity failure code, zero partial posting, and an S021 recovery case carrying event + code + attempted pack version + correlation. Never a silent choice.

**AC-3 — Failure taxonomy.** *(Bucket A — ready)* Given no-matching-rule / invalid-account / missing-mandatory-field / imbalance-beyond-tolerance / closed-period, Then each rejects with its own deterministic code from the closed enum and creates an S021 case; no generic "rule error"; no suspense posting; no silent redating.

**AC-4 — Idempotency.** *(Bucket A — ready)* Given a duplicate event (same envelope idempotency identity), Then the original result returns; no second journal, no second schedule effect, under concurrent delivery (live-DB test).

**AC-5 — Replay with dual-version audit.** *(Bucket A — ready, depends on the D-22 narrow engine change landing)* Given a corrected pack version activated and an authorized replay of a failed event, Then evaluation uses the currently active approved version and the audit trail preserves: originally attempted pack version, replay pack version, original failure, replay actor, replay reason, resulting journal/execution.

**AC-6 — Replay period behavior.** *(Bucket A — ready)* Given the original period is closed at replay time, Then the journal posts to the current open period with the original business date preserved as reference — never silently redated, never into a hard-closed period.

**AC-7 — Activation SoD.** *(Bucket A — ready, new engineering work, no precedent to reuse — see D-28 reconciliation note)* Given a user who created or materially changed pack version vX, When that same identity attempts activation of vX, Then activation is refused (identity-based, named result); a separately authorized user activates; replay permission is provably distinct from authoring and activation rights.

**AC-8 — Version traceability.** *(Bucket A for the mechanism / Bucket B for real diff content)* Given any journal generated by the engine from packs, Then inquiry (S220 drill) exposes the pinned pack version, and a mapping-change diff (before/after account) is reconstructable from audit for every version transition.

**AC-9 — Envelope enforcement.** *(Bucket A — ready to build now; end-to-end proof depends on D-06 producer work landing)* Given an event missing a mandatory envelope field, Then deterministic rejection naming the field; producers S039/S043A/S052 emit the canonical envelope (producer conformance tests pass).

**AC-10 — Exactly-one rule source.** *(Bucket C — schedule-effect component dependent on UQ-18/relieving-policy)* Static/architecture check: no AP/AR/Cash posting path constructs journals outside pack evaluation; zero direct GL writes anywhere in S023 scope. The rule-evaluation half of this claim does not depend on UQ-18/relieving-policy; the schedule-effect half (D-16/D-17) does — do not certify AC-10 as fully satisfied until those two dependencies are supplied.
