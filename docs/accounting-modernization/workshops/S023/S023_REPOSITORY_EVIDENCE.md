# S023 — Repository Evidence Against Every Workshop Decision (D-S023-01 … 38)

**Purpose:** validate the S023 Definition Workshop Pack's 38 decisions against what is actually built on `r1-integration` today. Nothing here accepts a PROPOSED option — this is evidence, not ratification. Full supporting detail lives in `S023_EXISTING_ARCHITECTURE_MAP.md` (architecture-wide facts) and `S023_CURRENT_EVENT_PAYLOADS.md` (exact payloads); this document maps that evidence onto each decision ID and states whether the pack's PROPOSED option fits reality.

**Read this first — three findings that change how several sections should be read:**

1. **The workshop pack understates its own information base.** The canonical registry it says is "not available" (`OPEN_QUESTIONS_AND_DECISIONS.md`, `canonical_registry.json`, `ACCOUNTING_MASTER_BACKLOG.md`) is tracked in git, zipped, at `docs/accounting-modernization/AutoMate2_Accounting_Backlog_Package_v1.1.zip`. It confirms CE-07/S023 as real (disposition `RETAINED`) but only as a one-line `EXPANSION_PENDING` stub — no richer contract exists there either. It also states CE-07's actual exit criteria: **"zero direct GL writes from operational services."** Evidence below shows this is currently violated by S039 and S043A.
2. **AP/AR/Cash do not flow through the S019/S020 engine today.** S039 and S043A post to GL via a direct synchronous HTTP call to `gl-service`, bypassing the event/outbox path and the posting engine entirely. S052 emits an event with zero consumers and never posts to GL. This means most of Section B and C's decisions are being made against events and flows that don't exist yet in engine-consumable form — this is more foundational than "define the mapping," it's "build the pipeline that doesn't exist."
3. **Two internal contradictions exist inside the pack itself**, discovered by comparing decisions against the actual engine code: D-S023-08's proposed rule-precedence model would require an engine change, which conflicts with D-S023-22's premise that the engine is unchanged; and D-S023-25's proposed replay policy is technically impossible under S021's actual (unmerged) idempotency-passthrough contract without either an engine change or a different recovery design. Both are flagged in place below and again in the feasibility matrix.
