## EPIC OBJECTIVE & BUSINESS PROBLEM
Dealership compensation — the second-largest expense line — posts to the GL correctly by department and store, ties to payroll-provider truth, and captures the dealership-specific mechanics (commission plans on deal gross, chargebacks on unwound deals, tech flag-hour absorption, period-end accruals) with governed rules and zero invented statutory math. Outcome: labor cost the Controller can certify by department; payroll clearing that zeroes; commission math that traces to plan + deal evidence; no statutory calculation performed uncertified.

## THE STATUTORY BOUNDARY (governs the whole epic)
**This epic is the GL/accounting side of payroll.** Gross-to-net statutory calculation (income-tax withholding, FICA/FUTA/SUTA, state/local rules, filing) is OWNED by the certified payroll source behind an adapter: either an external payroll provider file/API or a future certified in-house engine. CE-13 **never** computes statutory values: no rates, no withholding tables, no filing logic in code. Where authoritative statutory data is unavailable: `PAYROLL_SOURCE_NOT_CONFIGURED` truthful state; runs cannot post statutory lines; manual entry of provider-register figures is a valid labeled path (figures are ENTERED EVIDENCE with attestation, never computed); deterministic labeled test fixtures for certification; production-certified vs fixture behavior always distinguished. Never silently estimate a statutory value; block or exception instead.

## STORY CONTRACTS

**S025 Payroll+Close Rule Pack.** The pack story: matrix rows for every family below (earnings by type/department, employer liabilities, withholding liabilities, clearing, accruals, commission expense/payable, clawback, flag absorption) authored under approved S023 governance (author≠activator, versioned, simulate). Persona: Controller+Accounting. AC: every CE-13 journal pins an S025 version; simulate returns blueprints for all families; blank rows only.

**S108 Payroll Run GL Posting.** Persona: payroll accountant. Trigger: provider run file/API result (or attested manual register entry). Prereqs: mapping rows active for the run's earning/deduction/liability codes; period open. Workflow: import/enter register → validation (code coverage: every register code maps or run BLOCKS naming codes; totals cross-foot: gross = net + EE withholdings; DR total = CR total) → distribution preview by department/store/account (per employee-home-department config + operational splits from register) → approval (SoD: importer ≠ approver) → post ONE run journal: DR earnings expense by dept, DR employer-liability expense / CR EE-withholding liabilities by type, CR employer liabilities, CR payroll clearing (net pay). Clearing relief: payment execution via CE-09 (S043B run or provider-debit entry) relieves clearing — **clearing must return to zero per run** (tie AC). Duplicate-run prevention: idempotency (provider run id + period); overlapping-period same-population run ⇒ named refusal. Corrections: void-run = S218 symmetric reversal (refused after clearing relieved → adjustment-run path); adjustment runs post deltas with lineage. YTD: register-sourced YTD balances stored as evidence for reconciliation (not computed). AC: run journal = register byte-exactly on fixtures; unmapped code blocks; clearing zeroes after payment; duplicate refused; void symmetric; manual-entry path labeled + attested; no statutory value computed anywhere (static check: no rate math in payroll services).

**S109 Commission Engine.** Persona: F&I manager/payroll accountant. Scope: dealership commission computation from CONFIGURED PLANS applied to deal evidence — this is business-rule math (allowed), not statutory math. Plan model [tenant config, effective-dated, versioned like packs]: role (salesperson/FI/manager), basis (front gross, back gross, product-level, unit count, per accepted recap fields from CE-12 S084 snapshot [PUTR: snapshot contract]), rate structures (flat %, tiered volume, per-unit flat, spiffs as entered items), split rules, minimums/draws (draw = advance against commission: draw payment via payroll run; earned-vs-draw reconciliation). Workflow: period commission run → compute per plan vs deal snapshots → statement per employee (deal-level trace lines) → dispute/adjust ceremony (reason + audit) → approval → accrual journal (DR commission expense by dept / CR commission payable) → payable feeds S108 earnings (commission earning code) or direct payment per config. AC: computed commission = plan-applied-to-snapshot fixtures exactly, deal-traceable line by line; tier boundaries tested; splits conserve; adjustment ceremony audited; accrual reverses when paid through the run (no double expense — guard AC); plan changes prospective.

**S110 Chargeback Clawback Consumption.** Trigger: CE-12 events — deal unwind (S086), product cancellation (S093), reserve chargeback (S091) [PUTR: event payloads carry original deal + commission linkage]. Workflow: locate commissions paid/accrued on the affected deal → compute clawback per plan's chargeback terms (full/pro-rata per plan config) → clawback ceremony (visible to payroll accountant; employee-statement line) → journal: CR commission expense (or clawback income per matrix row structure) / DR commission payable or employee receivable item (CE-08, applyNumber=employee+deal) when already paid → recovery via next-run deduction (S108 deduction code) or repayment (CE-09 receipt). Guards: clawback exceeds remaining payable ⇒ receivable path, never negative net below configured floor [floor = plan/statutory-protection config; where jurisdiction limits deduction, config table — no invented labor law]. AC: clawback = plan math on fixtures; already-paid path creates receivable exactly; next-run deduction relieves it; double-clawback refused; every clawback deal-lineaged.

**S111 Compensation Accruals.** Period-end accruals: earned-unpaid wages (days between last run and period end — basis: register-derived daily rate × days, preview-approve), earned-unpaid commissions (S109 run accrued not yet paid — automatic tie), PTO/vacation liability (balances from provider/entered evidence × rate — preview-approve), bonus accruals (entered management figures w/ approval). All accruals auto-reverse next period (S218-linked reversing entries) [standing dealership month-end pattern]. AC: accrual = approved preview; auto-reversal posts on period open; nothing accrues from computed statutory values; close-report shows accrual completeness for CE-15 [PUTR: close checklist signal].

**S112 Tech Flag-to-Payroll Bridge.** Trigger: CE-11 S063 period-boundary event (flag hours, unapplied time, guarantee shortfall per tech) [PUTR: event contract — shared with CE-11]. Workflow: flag-hour earnings feed → tech earning lines into S108 run (flag rate × hours from operational truth; rates = pay-plan config), guarantee top-up line where shortfall, absorption already booked by CE-11 S063 (boundary: S063 books COST absorption in Fixed Ops; S112 carries EARNINGS into payroll — no double-book: reconciliation report proves flag-hour cost vs earnings tie). AC: tech earnings = hours × configured rates exactly; guarantee tops up to guaranteed figure; absorption-vs-earnings reconciliation ties on fixtures; missing rate config blocks naming the tech/plan.
