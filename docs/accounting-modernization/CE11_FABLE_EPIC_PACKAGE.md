## WORKSTREAM A — REPAIR-ORDER ACCOUNTING (S059, S060, S061, S063, S064)

**S059 RO Close Posting (All Pay Types).** Consumes `service.ro.closed` (lines: labor/parts/sublet/misc/fees, each carrying pay type C=customer, W=warranty, I=internal + amounts, cost, tech, opcode, tax result ref). Journal structure per pay type (accounts pending; roles fixed): **C:** DR AR-customer (or cash via S052 when paid at cashier — receipt applies to the RO item) / CR labor sales, parts sales, sublet income, fee lines per S125, tax per S124 result; DR COS labor (offset labor-in-process/applied labor), DR COS parts (offset inventory via S066 relief event linkage), DR COS sublet (offset sublet accrual from S062). **W:** DR warranty claim receivable (creates CE-08 claim item, applyNumber=claim#) / CR sales at warranty rates; COS identically. **I:** DR internal expense/policy account of the charged department / CR internal sales; COS identically — no external receivable. **Mixed-pay RO:** one journal, lines split by pay type exactly per the operational distribution; Σ segments = RO totals to the cent (conservation AC). Rounding per approved D-19. AC: one RO close = exactly one journal (idempotent on RO#+closeVersion); per-pay-type goldens byte-exact; mixed-pay conservation; C-type without tax result ⇒ blocked/exception (never estimated); duplicate close event returns original.
**S060 RO Reopen/Void Auto-Reversal.** `service.ro.reopened|voided` ⇒ automatic S218-linked reversal of the close journal (and of its schedule effects: claim item negated with lineage, AR item restored/closed) — deterministic, exactly-once (idempotent on RO#+closeVersion reversed). Re-close after reopen posts a NEW journal (new closeVersion) — never edits. Guards: reopen after the claim item was cash-applied ⇒ REFUSED with named result (correction path = claim adjustment per S065, preserving application history — same conservation boundary as CE-09 D-01); void after customer payment applied ⇒ refused → refund/adjustment path. AC: reopen reverses byte-symmetrically (TB restored); race on simultaneous reopen+payment resolves to one winner; refusal paths named + audited.
**S061 Labor WIP Mode & Open-RO Report.** Tenant/entity election [SAFE_CONFIGURATION]: **WIP mode** (labor accrues to WIP at time-flag: DR labor-in-process / CR applied-labor accrual; relieved into COS at close) vs **direct mode** (labor hits COS only at close; open-RO exposure is memo). Open-RO/WIP report (Accounting side): open ROs w/ age, accumulated labor/parts value, pay-type mix, WIP GL tie (WIP mode: report Σ = WIP account balance — tie-out AC). Mode change is effective-dated, prospective only, ceremony w/ impact preview. AC: mode election drives both journal structures correctly on goldens; WIP tie-out $0; report drills to RO accounting detail.
**S063 Unapplied Time & Tech Guarantee.** Tech clocked time not applied to ROs + guarantee shortfall (guaranteed hours − flagged hours) post per matrix rows (DR unapplied-labor/guarantee expense / CR applied-labor or accrual) on the payroll-period boundary event; **actual wage/payroll math is CE-13/WD-01 scope — this story books the labor-cost absorption effects from operational time data only** [PUTR: period-boundary event + CE-13 contract]. Guarantee terms per tech = configuration. AC: unapplied+guarantee journal equals fixture math from entered time data exactly; zero payroll calculation present; period idempotency.
**S064 Deferred Maintenance Contracts v1.** Sold maintenance contract ⇒ DR cash/AR / CR deferred revenue (creates CE-08 deferred item, applyNumber=contract#). Redemption on an RO ⇒ recognize: DR deferred revenue / CR service revenue for the redeemed value, relieving the item partially; contract balance inquiry. **Recognition trigger = redemption-based only in v1** (per accepted v1 scope); ratable/breakage recognition **excluded, recorded** — D-CE11-01 flags the *breakage/expiry* rule (expired unredeemed balance treatment) as the one genuine open accounting rule in this story: **interim = balances remain deferred until an approved breakage policy exists; nothing auto-recognizes.** AC: sale creates item; redemption relieves exactly; expiry does NOT recognize (interim proof); contract balance = item remaining always.

## WORKSTREAM B — SUBLET & FACTORY/CLAIM RECEIVABLES (S062, S065)

**S062 Sublet PO Lifecycle.** Sublet PO raised from RO (vendor, est. cost) → vendor invoice arrives via CE-09 S039 (matched to sublet PO — this IS a PO source for the S039 adapter: `SUBLET_PO` source registered; PUTR: adapter registration) → accrual at RO close if invoice not yet received (DR COS sublet / CR sublet accrual, item applyNumber=subletPO#) → invoice posting relieves accrual (never double-costs: invoice-after-accrual posts against the accrual item, variance to COS). AC: close-before-invoice accrues; invoice relief exact w/ variance line; invoice-before-close costs directly, close does not re-accrue (state machine tested); tie: sublet accrual account = Σ open sublet items.
**S065 Warranty Claim Receivable Lifecycle.** Claim item born at W-type RO close (S059) → submitted (status) → factory remittance applies via CE-09 receipt (applyNumber=claim#) → short-pay disposition per approved S049 pattern: write-down (journal per matrix rows) or transfer-to-customer-responsibility item — explicit, audited clerk action, never silent → denial ⇒ full disposition ceremony → aging per CE-08 S027 with factory-age exception rules. Claim adjustment (supplement/correction) = posted journal adjusting the item, S218-linked. AC: claim lifecycle statuses tie to item states; partial factory payment leaves exact remainder; short-pay disposition conserves to the cent; aging report Σ = warranty receivable GL balance; every disposition audited w/ reason.

## WORKSTREAM C — PARTS MOVEMENT & VALUATION (S066, S067, S068, S072)

**S066 Parts Movement Posting & Tie-Out.** Approved movement families (each an event → matrix rows; roles fixed): receipt (DR inventory / CR AP-accrual or AP via S039 match), RO issue (CR inventory / DR COS-parts, linked into S059's journal or companion per event design — one journal per movement, no double relief: PUTR event granularity w/ Parts module), counter sale (CR inventory / DR COS + the sale via CE-09), return-to-stock (reverse issue), return-to-vendor (CR inventory / DR AP-debit-memo item), internal issue (DR internal expense), adjustment (→ S069 ceremony only). **Negative on-hand:** D-CE11-02 — genuine rule: allow-with-exception-flag vs hard-block; **interim = movement posts, item flagged NEGATIVE_ON_HAND exception (CE-08 S027 rule), reconciliation shows it loudly** — visible, never silent; ratify at certification. **Perpetual-to-GL tie-out:** nightly + on-demand per entity/store: Σ(qty × unit value) per the S072 valuation config = inventory control GL; $0 or loud variance with movement-level drill. AC: one movement = one journal, idempotent per movementId; every family golden byte-exact; tie-out $0 on any fixture sequence + injected variance caught; no movement bypasses the engine.
**S067 OEM Price-Tape Revaluation.** Tape load (adapter; manual import truthful) → **preview**: per-part old/new value, Σ revaluation effect → **explicit approval ceremony posts** (DR/CR inventory vs price-variance per matrix rows) — nothing auto-posts on tape load [preview-approve pattern; defuses the trigger question safely]. Effective-dated part costs; history. AC: preview Σ = posted journal exactly; unapproved tape changes nothing in GL; post-revaluation tie-out still $0; tape reload idempotent.
**S068 Obsolescence Provision & Scrap.** Aging-based provision **preview** from configured band percentages [SAFE_CONFIGURATION] → explicit approval posts provision (DR obsolescence expense / CR allowance); scrap ceremony: physical disposal writes off qty+value (CR inventory / DR allowance-then-expense per matrix rows) w/ reason + distinct permission + threshold refusal [reuse CE-08 D-CE08-02 outcome; PUTR]. AC: provision = approved preview exactly; scrap conserves tie-out; allowance never goes debit (guard).
**S072 Parts Valuation Config & Landed Cost (R5-sequenced; config model built early because S066 reads it).** Valuation method election per entity [replacement/average per accepted config scope — method list from accepted source; no method invented], landed-cost components (freight/duty allocation rules as configuration; allocation posts within receipt journal), effective-dated, prospective-only changes w/ ceremony + revaluation preview where method change requires it. AC: S066 values movements per active config; landed components allocate exactly per rule; method change prospective + previewed.
