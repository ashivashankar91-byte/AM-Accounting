## 1. Service Fails to Start

### 1.1 Port Already in Use

**Symptoms:**
```
Error: listen EADDRINUSE: address already in use :::3010
```
or Docker reports:
```
Bind for 0.0.0.0:3010 failed: port is already allocated
```

**Root cause:** A previous instance of the service (or another process) is still bound to the port.

**Resolution:**
```bash
# Find the PID using the port (example: port 3010)
lsof -ti:3010

# Kill the process
lsof -ti:3010 | xargs kill -9 2>/dev/null

# Then restart the specific service
docker compose up -d gl-service

# Verify it starts healthy
sleep 5 && curl -s http://localhost:3010/health | jq '.status'
```

---

### 1.2 Missing Required Environment Variable

**Symptoms:**
```
Error: AMACC_JWT_SECRET is required
Error: JWT_SECRET is required
Error: ADMIN_API_KEY is required
```
or the container exits immediately with code 1.

**Root cause:** One or more required environment variables are not set in `.env`, or the `.env` file was not loaded.

**Resolution:**
```bash
# Check which variables are missing
grep -E "^(AMACC_JWT_SECRET|JWT_SECRET|ADMIN_API_KEY|AMACC_INTERNAL_TOKEN)=" .env

# If any are missing or empty, add them to .env
echo 'AMACC_JWT_SECRET=your-local-demo-secret-minimum-32-characters' >> .env
echo 'JWT_SECRET=your-local-demo-secret-minimum-32-characters' >> .env
echo 'ADMIN_API_KEY=local-admin-api-key' >> .env
echo 'AMACC_INTERNAL_TOKEN=amacc-internal-dev' >> .env

# Restart all services to pick up the new values
docker compose down
docker compose up -d
```

> **Important:** `AMACC_JWT_SECRET` and `JWT_SECRET` must contain the **same value** across all services, otherwise JWTs generated by auth-service will be rejected by all other services.

---

### 1.3 Service Crashes on Startup (Prisma Error)

**Symptoms:**
```
PrismaClientInitializationError: Can't reach database server
P1001: Can't reach database server at 'postgres:5432'
```

**Root cause:** The service started before PostgreSQL was fully healthy, or the `depends_on` condition was not respected.

**Resolution:**
```bash
# Confirm postgres is healthy first
docker compose ps postgres

# Restart the failing service
docker compose restart gl-service

# If it crashes again, check the full logs
docker compose logs --tail=100 gl-service
```

---

### 1.4 Out of Memory (OOM Kill)

**Symptoms:** Container repeatedly restarts with exit code 137.

**Root cause:** Docker Desktop memory limit is too low for the full service stack (38+ services).

**Resolution:**
1. Open Docker Desktop → Settings → Resources → Memory.
2. Increase to at least **8 GB** (16 GB recommended for all services simultaneously).
3. Restart Docker Desktop.
4. `docker compose up -d`

## 2. Database Connection Failures

### 2.1 Wrong Port (5432 vs. 5433)

**Symptoms:**
```
psql: error: connection to server on socket "/tmp/.s.PGSQL.5432" failed
Error: connect ECONNREFUSED 127.0.0.1:5432
```

**Root cause:** The host maps PostgreSQL to port **5433**, not the default 5432. Scripts or connections pointed at 5432 will fail.

**Resolution:**
```bash
# Always use port 5433 from the host
psql "postgresql://amacc:amacc_dev@localhost:5433/amacc"

# For seed scripts — ensure DATABASE_URL uses 5433
export DATABASE_URL="postgresql://amacc:amacc_dev@localhost:5433/amacc"

# In .env (host-side connections)
DATABASE_URL=postgresql://amacc_app:amacc_app_dev@localhost:5433/amacc

# IMPORTANT: Inside docker-compose services, the hostname is 'postgres' on port 5432
# (internal Docker network). Only host-side tools need port 5433.
```

---

### 2.2 Authentication Failed

**Symptoms:**
```
FATAL: password authentication failed for user "amacc"
```

**Root cause:** The PostgreSQL user credentials in `.env` do not match the credentials set when the container was first created. This can happen if the container was recreated with new credentials but the volume was not wiped.

**Resolution:**
```bash
# Option A: Wipe the volume and recreate (data loss — use before seeding)
docker compose down -v
docker compose up -d postgres
sleep 15
# Now re-run migrations and seed

# Option B: Connect with the original superuser and reset the password
docker exec -it am-accounting-r1-integration-postgres-1 psql -U amacc -c \
  "ALTER USER amacc_app PASSWORD 'amacc_app_dev';"
```

---

### 2.3 Database Does Not Exist

**Symptoms:**
```
FATAL: database "amacc" does not exist
```

**Root cause:** The `amacc` database was not created. This happens if the Postgres container started with a different `POSTGRES_DB` value or was recreated without a volume reset.

**Resolution:**
```bash
docker exec -it am-accounting-r1-integration-postgres-1 psql -U amacc -c \
  "CREATE DATABASE amacc;"
# Then run migrations
bash scripts/migrate-all.sh
```

## 3. Seed Failures

### 3.1 Schema Mismatch

**Symptoms:**
```
PostgresError: column "xyz" of relation "journal_entry" does not exist
PrismaClientKnownRequestError: Invalid column name
```

**Root cause:** A migration was applied in code but not yet run against the database, causing the seed script to reference columns that do not yet exist.

**Resolution:**
```bash
# Run all pending migrations first
bash scripts/migrate-all.sh

# Or run the migrator container
docker compose run --rm migrator

# Then re-run seed
yarn seed:all-159-demo --reset
```

---

### 3.2 RLS Policy Violation

**Symptoms:**
```
PostgresError: new row violates row-level security policy for table "journal_entry"
Error: 42501 - permission denied
```

**Root cause:** The seed script is connecting as `amacc_app` (the application user), but RLS policies require tenant-scoped context set via `set_config('app.tenant_id', ...)`. Alternatively, the seed must run as the superuser `amacc` to bypass RLS.

**Resolution:**
```bash
# Ensure the seed script uses the superuser connection string
# In scripts/seed-all-159-demo.ts, confirm the connection uses:
# postgresql://amacc:amacc_dev@localhost:5433/amacc  (superuser)
# NOT:
# postgresql://amacc_app:amacc_app_dev@localhost:5433/amacc  (app user, RLS enforced)

# Set the correct DATABASE_URL before running seed
export DATABASE_URL="postgresql://amacc:amacc_dev@localhost:5433/amacc"
yarn seed:all-159-demo --reset
```

---

### 3.3 Duplicate Key Violation (Idempotency Failure)

**Symptoms:**
```
PostgresError: duplicate key value violates unique constraint "tenant_pkey"
```

**Root cause:** The seed was run without `--reset`, and some records already exist that cannot be upserted (usually because the upsert logic is missing for a specific table).

**Resolution:**
```bash
# Use --reset to wipe demo tenant data before re-seeding
yarn seed:all-159-demo --reset
```

If `--reset` does not clear the conflict:
```bash
# Manually delete the conflicting tenant data
psql "postgresql://amacc:amacc_dev@localhost:5433/amacc" -c \
  "DELETE FROM tenant WHERE id='tenant-kunes';"
# Then re-seed
yarn seed:all-159-demo
```

---

### 3.4 Seed Hangs / Timeout

**Symptoms:** Seed script runs for more than 3 minutes without completing.

**Root cause:** A service the seed depends on (auth-service, tenant-service) is not responding. Or RabbitMQ is not processing events, causing event-driven seed steps to block.

**Resolution:**
```bash
# Check that auth-service and tenant-service are healthy
curl http://localhost:3001/health
curl http://localhost:3002/health

# Check RabbitMQ queue depth
curl -s -u guest:guest http://localhost:15673/api/queues | jq '.[].messages'
# If queues show large backlogs, restart RabbitMQ
docker compose restart rabbitmq

# Interrupt the seed (Ctrl+C) and retry
yarn seed:all-159-demo --reset
```

## 4. Frontend Blank Screen

### 4.1 Vite Not Running

**Symptoms:** `http://localhost:5174` returns `ERR_CONNECTION_REFUSED`.

**Root cause:** The Vite dev server (`web` container or local `yarn dev`) is not running.

**Resolution:**
```bash
# Via docker-compose
docker compose up -d web
sleep 5
curl -s -o /dev/null -w "%{http_code}" http://localhost:5174

# Or run locally (outside Docker)
cd apps/web && yarn dev --port 5174
```

---

### 4.2 Blank Screen with No Console Errors

**Symptoms:** Page loads (HTTP 200) but renders nothing — white screen.

**Root cause:** React failed to mount due to a JavaScript exception that is not surfaced in the terminal. Usually a missing environment variable (`VITE_API_BASE_URL`), or a dynamic import failure.

**Resolution:**
1. Open browser DevTools → Console tab. Look for red errors.
2. Check that `VITE_API_BASE_URL` is set in `apps/web/.env.local`:
   ```
   VITE_API_BASE_URL=http://localhost:3100
   ```
3. If the error mentions a missing module, ensure `node_modules` is intact (see § 11).
4. Hard-reload the page: `Cmd+Shift+R` (macOS) or `Ctrl+Shift+R` (Windows).

---

### 4.3 Proxy Configuration Error

**Symptoms:** Frontend loads but all API calls return 502 or CORS errors in the browser console.

**Root cause:** The Vite proxy config in `vite.config.ts` is pointing to the wrong gateway address or port.

**Resolution:**
```bash
# Check the proxy config
grep -A5 "proxy" apps/web/vite.config.ts
# Should show: target: 'http://localhost:3100'

# If the target is wrong, update vite.config.ts:
# proxy: { '/api': { target: 'http://localhost:3100', changeOrigin: true } }
```

## 5. Gateway 502/503 Errors

### 5.1 Downstream Service Not Healthy

**Symptoms:**
```
502 Bad Gateway
{"error":"Service unavailable","code":"UPSTREAM_UNAVAILABLE"}
```

**Root cause:** The API gateway attempted to route to a downstream service that is not running or not healthy.

**Resolution:**
```bash
# Identify which service is failing
curl -s http://localhost:3100/health | jq '.services'

# Restart the failing service (example: gl-service)
docker compose restart gl-service
sleep 5
curl http://localhost:3010/health

# If the service won't start, check its logs
docker compose logs --tail=100 gl-service
```

---

### 5.2 Service Not Registered with Gateway

**Symptoms:** 404 Not Found from gateway for a specific module (e.g., `/api/v1/oem`).

**Root cause:** The service failed its health check, so the gateway did not register it in the service registry.

**Resolution:**
```bash
# Force restart the service and wait for it to become healthy
docker compose stop oem-service && docker compose start oem-service
sleep 10
curl http://localhost:3052/health

# Check gateway service registry (if applicable)
curl http://localhost:3100/admin/services 2>/dev/null | jq '.'
```

## 6. Authentication Failures

### 6.1 JWT Key Mismatch

**Symptoms:**
```
401 Unauthorized
{"error":"Invalid token","code":"JWT_INVALID"}
JsonWebTokenError: invalid signature
```

**Root cause:** The `AMACC_JWT_SECRET` / `JWT_SECRET` value differs between auth-service (which issued the token) and the downstream service (which is verifying it).

**Resolution:**
```bash
# Confirm both secrets are identical in .env
grep -E "^(AMACC_JWT_SECRET|JWT_SECRET)=" .env

# If they differ, set them to the same value and restart all services
# Edit .env — ensure AMACC_JWT_SECRET=<value> and JWT_SECRET=<same value>
docker compose down
docker compose up -d
```

---

### 6.2 User Not in Database

**Symptoms:** Login returns 401 even with the correct password.

**Root cause:** The demo user was not created by the seed script (seed may have partially failed).

**Resolution:**
```bash
# Check if the user exists
psql "postgresql://amacc:amacc_dev@localhost:5433/amacc" -t -c \
  "SELECT email, status FROM \"user\" WHERE email='admin@kunes-demo.local';"
# Expected: admin@kunes-demo.local | ACTIVE

# If empty, re-run seed
yarn seed:all-159-demo --reset
```

---

### 6.3 User Account Inactive

**Symptoms:** Login returns 403 with message "Account is inactive."

**Root cause:** The user account status is not `ACTIVE` — it may be `PENDING` or `SUSPENDED` due to a partial seed.

**Resolution:**
```bash
psql "postgresql://amacc:amacc_dev@localhost:5433/amacc" -c \
  "UPDATE \"user\" SET status='ACTIVE' WHERE tenant_id='tenant-kunes';"
# Or run a full reset
yarn seed:all-159-demo --reset
```

## 7. RLS / Permission Errors

### 7.1 `set_config` Not Called

**Symptoms:**
```
PostgresError: permission denied for table journal_entry
ERROR: new row violates row-level security policy
```
in application logs (not seed scripts).

**Root cause:** The application middleware that calls `SET LOCAL app.tenant_id = '...'` before each query is not being invoked. This is typically a missing RLS middleware call in the service's database transaction wrapper.

**Resolution:**
```bash
# Verify the RLS middleware is present in the failing service
grep -r "set_config\|app.tenant_id\|rls" services/gl-service/src/infrastructure/

# If the middleware is missing, this is a code bug, not a demo environment issue
# As a temporary workaround for demo, connect as superuser (no RLS):
# This is acceptable ONLY in the local demo environment
```

---

### 7.2 Wrong Role in RLS Policy

**Symptoms:** The application user can read but cannot write (or vice versa), even though the business role allows it.

**Root cause:** The PostgreSQL RLS policy checks `current_setting('app.role')` and the middleware is setting it to a different value than what the policy expects.

**Resolution:**
```bash
# Check what role the session is presenting
psql "postgresql://amacc_app:amacc_app_dev@localhost:5433/amacc" -c \
  "SELECT current_setting('app.role', true);"

# If the setting is empty, the middleware is not running
# Check service middleware initialization in the relevant service
```

## 8. Journal Balance Errors

### 8.1 Seed Produces Unbalanced Journal

**Symptoms:**
```
[seed] ERROR: Journal JE-SEED-XXX is unbalanced: DR $12500.00 ≠ CR $12000.00
```

**Root cause:** A seed script bug introduced a debit/credit mismatch in one of the seeded journal entries. This most commonly occurs after a merge conflict in the seed file that changed an amount on one side without updating the other.

**Resolution:**
```bash
# Identify which journal is unbalanced
psql "postgresql://amacc:amacc_dev@localhost:5433/amacc" -t -c "
SELECT je.id, je.description,
  SUM(CASE WHEN jl.side='DEBIT' THEN jl.amount ELSE 0 END) as dr,
  SUM(CASE WHEN jl.side='CREDIT' THEN jl.amount ELSE 0 END) as cr
FROM journal_entry je
JOIN journal_line jl ON jl.journal_id = je.id
GROUP BY je.id, je.description
HAVING ABS(
  SUM(CASE WHEN jl.side='DEBIT' THEN jl.amount ELSE 0 END) -
  SUM(CASE WHEN jl.side='CREDIT' THEN jl.amount ELSE 0 END)
) > 0.01;"

# If caused by seed data bug, fix the seed script and re-run
yarn seed:all-159-demo --reset
```

---

### 8.2 Posting Blocked by Balance Check

**Symptoms:** The demo journal entry cannot be posted — UI shows "Journal must be balanced before posting."

**Root cause:** During the Tier A Step A-3 demo step, the presenter entered a debit or credit amount that does not equal the other side.

**Recovery:**
```bash
# During the demo: edit the journal entry amounts so DR = CR
# Navigate to /gl/journals/:id → Edit → fix the amount → re-submit
```

## 9. Migration Not Applied

### 9.1 Prisma Client Outdated

**Symptoms:**
```
PrismaClientInitializationError: Prisma has detected that this project was built with Prisma Client that is not compatible
P3005: The database schema is not empty
```

**Root cause:** The Prisma client was not regenerated after a schema change, or migrations were run in a different order than expected.

**Resolution:**
```bash
# Regenerate Prisma clients for all services
yarn workspaces foreach --all run prisma generate

# Or for a specific service
yarn workspace @am/gl-service prisma generate

# Deploy pending migrations
yarn workspace @am/gl-service prisma migrate deploy
```

---

### 9.2 Which Service Needs Migration

**Symptoms:** One or more services start with errors but it is unclear which has a pending migration.

**Resolution:**
```bash
# Check migration status for all key services
for svc in gl-service eom-service payroll-service apar-service coa-service \
           approval-service close-service migration-service compliance-service \
           tax-service oem-service fixedops-service parts-accounting-service; do
  echo "=== $svc ==="
  DATABASE_URL="postgresql://amacc:amacc_dev@localhost:5433/amacc" \
    npx prisma migrate status \
    --schema="services/$svc/prisma/schema.prisma" 2>&1 | \
    grep -E "up to date|pending|error"
done
```

## 10. Playwright Test Failures

### 10.1 Browser Not Installed

**Symptoms:**
```
Error: browserType.launch: Executable doesn't exist at /path/to/chromium
```

**Root cause:** Playwright browsers were not installed after `yarn install`.

**Resolution:**
```bash
npx playwright install chromium
# Or install all browsers
npx playwright install
```

---

### 10.2 Wrong Base URL

**Symptoms:**
```
Error: page.goto: net::ERR_CONNECTION_REFUSED http://localhost:3000
```

**Root cause:** The Playwright config `baseURL` is set to port 3000, but the demo frontend runs on port 5174.

**Resolution:**
```bash
# Check the playwright config
grep "baseURL" playwright.config.ts

# Should be: baseURL: 'http://localhost:5174'
# If not, update the config or pass the URL at runtime:
BASE_URL=http://localhost:5174 npx playwright test
```

---

### 10.3 Test Fails Because App Not Running

**Symptoms:**
```
Error: page.goto: net::ERR_CONNECTION_REFUSED
```

**Root cause:** The Playwright tests were started before the full service stack was ready.

**Resolution:**
```bash
# Ensure all services are healthy first
curl -s http://localhost:5174 > /dev/null && echo "Frontend OK" || echo "Frontend NOT READY"
curl -s http://localhost:3100/health | jq '.status'

# Start playwright only after confirming the stack is up
npx playwright test
```

## 11. node_modules Symlink Issue

### 11.1 Symlink from Previous Worktree

**Symptoms:**
- `yarn install` silently succeeds but packages are missing or wrong versions
- Import resolution errors in service tests
- `ls -la node_modules` shows `node_modules -> ../am-accounting-r1-cert/node_modules`

**Root cause:** When this repository was checked out as an additional Git worktree alongside another worktree (e.g., the R1 certification worktree), Yarn may have created a symlink from `node_modules` to the original worktree's `node_modules`. If the linked worktree is removed or reset, the symlink becomes broken.

**Resolution:**
```bash
# Verify the issue
ls -la node_modules

# If it is a symlink, remove it and reinstall
rm node_modules  # removes the symlink (not the linked directory)
yarn install
# or: yarn install --frozen-lockfile

# Verify the result
ls -la node_modules | head -1
# Should show: drwxr-xr-x (a real directory, not -> ...)
```

## 12. esbuild / Vite Alias Errors

### 12.1 `.prisma/gl-client` Path Not Resolved

**Symptoms:**
```
Error [ERR_MODULE_NOT_FOUND]: Cannot find module '.prisma/gl-client'
Build failed with 1 error:
  node_modules/.prisma/gl-client/index.js: No such file or directory
```
or in Vite:
```
[vite] Failed to resolve import ".prisma/gl-client" from "services/gl-service/src/..."
```

**Root cause:** The `@prisma/client` package generates service-specific clients in `.prisma/<output-name>` directories. The GL service uses a custom `output` path in its `schema.prisma`. If the client was not generated, the path does not exist. Vite and esbuild need explicit aliases to resolve these paths during bundling and testing.

**Resolution:**
```bash
# Step 1: Regenerate the GL service Prisma client
yarn workspace @am/gl-service prisma generate

# Step 2: Verify the generated client exists
ls node_modules/.prisma/gl-client/

# Step 3: If running Vite and the alias is missing, check vite.config.ts
# The resolve.alias section should include:
# '.prisma/gl-client': path.resolve(__dirname, 'node_modules/.prisma/gl-client')

# Step 4: For Jest / Vitest test runs, check moduleNameMapper in jest.config.ts:
# '.prisma/gl-client': '<rootDir>/../../node_modules/.prisma/gl-client'
```

---

### 12.2 Multiple Prisma Clients Conflicting

**Symptoms:**
```
PrismaClientValidationError: The `prisma` instance cannot be created because ...
Error: There are multiple instances of Prisma Client active
```

**Root cause:** Multiple services import from different Prisma client paths, and one of them resolves to a stale or incompatible version.

**Resolution:**
```bash
# Regenerate all Prisma clients from scratch
yarn workspaces foreach --all run prisma generate

# If the issue persists, clear and reinstall
rm -rf node_modules/.prisma
yarn workspaces foreach --all run prisma generate
```

## Quick Reference — Most Common Issues

| Symptom | Most Likely Cause | Quick Fix |
|---------|-----------------|-----------|
| 401 on all API calls | JWT secret mismatch | Check `.env` AMACC_JWT_SECRET = JWT_SECRET, restart services |
| Seed fails with RLS error | Running as app user, not superuser | `export DATABASE_URL=postgresql://amacc:amacc_dev@localhost:5433/amacc` |
| Service won't start (exit 1) | Missing env var | Check `.env` for AMACC_JWT_SECRET, JWT_SECRET, ADMIN_API_KEY |
| Database connection refused | Wrong port (5432 vs 5433) | Use port 5433 for all host-side connections |
| Frontend blank screen | VITE_API_BASE_URL missing | Add to `apps/web/.env.local` |
| node_modules import errors | Symlink from old worktree | `rm node_modules && yarn install` |
| `.prisma/gl-client` not found | Prisma client not generated | `yarn workspace @am/gl-service prisma generate` |
| 9/9 verify fails | Seed didn't complete cleanly | `yarn seed:all-159-demo --reset` |
| Playwright 404 / connection refused | Wrong baseURL or app not running | Set `BASE_URL=http://localhost:5174`, ensure stack is up |
| Period close state wrong | Seed state corruption | `yarn seed:all-159-demo --reset` |
