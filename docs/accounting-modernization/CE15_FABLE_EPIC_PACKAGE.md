## OBJECTIVE & BUSINESS PROBLEM
Month-end at a dealership is a deadline sport: schedules must tie, factory statements must file, the Controller must sign something they can defend. Today "closed" is a feeling; this epic makes it a governed state machine — **operational completion → accounting readiness → PRELIMINARY_CLOSED → FINAL_CLOSED → statutory-filing readiness → (external filing = boundary, not claimed)** — with evidence at every hop, SoD on every authority, and reporting drawn from the same ledger that produced the TB.

## GLOBAL RULES

Period state authority remains S008/S209 (CE-06/CE-02) — this epic ORCHESTRATES close over that control, it does not fork period logic. Upstream: CE-07..CE-14 final integrated behavior consumed; every not-yet-final contract point marked PENDING_UPSTREAM_TECHNICAL_RECONCILIATION (PUTR), never blocking independent build.

## CLOSE STATE MODEL (authoritative, used everywhere)
Per (tenant × legal entity × period): `NOT_READY → READY_WITH_EXCEPTIONS → READY → PRELIMINARY_CLOSED → FINAL_CLOSED`; side states `REOPEN_PENDING_APPROVAL` (from either closed state) and `STATUTORY_SOURCE_UNAVAILABLE` (statutory-readiness dimension). Distinctions enforced in data + UI: **operational completion** (module activity done — signals from CE-09/11/12/13/14 readiness feeds [PUTR]) ≠ **accounting readiness** (reconciliations tied + exceptions dispositioned) ≠ **preliminary close** (soft lock: postings refused except allowlisted late-posting roles per S008 rules) ≠ **final close** (hard lock; posting refusal absolute; changes only via governed reopen or post-close adjustment into the open period) ≠ **statutory filing readiness** (packages rendered + certified) ≠ **external filing/submission** (NOT claimed; export + recorded-response boundary only — same principle as CE-14). SoD (identity-based, server-enforced, per approved D-S023-28 pattern): close initiation ≠ exception override ≠ final-close authority ≠ reopen approval ≠ post-close adjustment ≠ statutory evidence approval — six distinct permissions; no identity may both override an exception and grant final close for the same period [SECURITY].

## STORY CONTRACTS

**S113 Close Calendar Task Engine.** Persona: Controller/close owner + task assignees. Close calendar per entity/period: task templates (daily/monthly/quarterly/annual sets), ownership, due dates keyed to close-day offsets, dependencies (task blocked-by), evidence attachment per task, status flow (OPEN→IN_PROGRESS→DONE→VERIFIED), escalation on overdue [thresholds config]. The calendar DRIVES the readiness roll-up: readiness = f(mandatory tasks VERIFIED + module signals + reconciliation states + exception queue empty-or-overridden). Recurring/reversing journal orchestration: scheduled recurring templates and accrual auto-reversals surface as calendar tasks linking to their posted journals (posting itself via CE-07; the engine schedules and evidences, never posts around it). AC: readiness state = deterministic function of inputs on fixtures; dependency blocking works; task evidence immutable once VERIFIED; calendar clone-to-next-period ceremony.

**S114 Reconciliation Module & PBC Export.** Persona: staff accountant/Controller/auditor-facing. Reconciliation register per period: every controlled account/module surface (bank via CE-09 S054x, AP/AR/schedules via CE-08 tie-outs, payroll clearing via CE-13, vehicle/floorplan via CE-12, parts perpetual via CE-11, tax via CE-10 three-way, OEM receivables via CE-14, intercompany via CE-06 pass-2 [PUTR]) registers its reconciliation with status (UNRECONCILED / RECONCILED_WITH_EXCEPTIONS / RECONCILED), preparer/reviewer SoD, tie evidence (system tie-out result refs where automated; attached evidence where manual), and sign-off. **PBC (Provided-By-Client) export:** auditor evidence package assembling registered reconciliations + statements + snapshots + selected journals into a structured export (retained, hash-stamped, audit-logged) — export only; no auditor portal claimed. AC: register completeness gates readiness (unregistered mandatory account ⇒ NOT_READY); preparer≠reviewer enforced; PBC export reproducible byte-stably for a FINAL_CLOSED period.

**S115 Pre-Close Scrub Reports.** Persona: staff accountant. Deterministic scrub suite run on demand/scheduled pre-close: unposted/draft journals aging, suspense-pattern detection (accounts flagged clearing-type with non-zero balance), unmatched schedule references, stale open items past thresholds, unapplied credits, negative-on-hand parts flags (CE-11), unfunded delivered deals/SOT (CE-12), missing tax results (CE-10), DLQ backlog (S021), missing mappings hit-count. Each finding → exception queue item with disposition workflow (FIX_LINK: deep-link to the owning surface / OVERRIDE with reason+SoD / DEFER with justification). AC: every scrub rule fires on its fixture; override requires the distinct permission + reason; findings drill to source; scrub results immutable per run.

**S116 Year-End Close.** Persona: Controller + final-close authority. Annual ceremony over 12 FINAL_CLOSED periods: year-end validation suite (all periods closed, TB rolls, RE continuity), **retained-earnings roll**: income-statement account closure into retained earnings per the fiscal-year rule — the roll posts THROUGH the engine as a governed year-end journal set (matrix rows for RE/closing structure, blank values standing rule), idempotent per fiscal year, reversible only via governed reopen-year ceremony (dual SoD: reopen approval + final-close authority). Opening-balance establishment for the new year proven equal to closing. Comparative-history integrity: prior-year figures frozen for comparative reporting. AC: roll = Σ P&L exactly on fixtures; opening = closing proof; second roll attempt returns original (idempotent); reopen-year reverses with lineage and re-locks only after re-certification.

**S117 Year-End Tax Pack.** Persona: Controller/external tax preparer. Year-end evidence package for the entity's tax preparation: fixed/rolling schedules the preparer needs (TB by period, statement packages, depreciation/fixed-asset summaries WHERE a source exists — fixed-asset subledger is not in the 159; the pack includes the GL-derived views and entered-evidence attachments, truthfully labeled; no invented asset register), book-tax difference WORKSHEET surfaces (entered/imported adjustments as evidence — **no tax computation**; statutory content = preparer's domain), export retained + hash-stamped. STATUTORY_SOURCE_UNAVAILABLE state where a required source is absent. AC: pack contents reproducible for a closed year; every sheet labeled by source (system-derived vs entered evidence); no tax math anywhere (static check).

**S119 Daily Operating Control (DOC).** Persona: dealer principal/GM/Controller. The dealership daily: per store/entity/day — sales/gross by department, expense pace, cash position (CE-09 S057 feed), schedule exposure highlights (CIT aging, SOT, warranty aging), close-task pulse. Server-computed from posted truth + operational feeds (source-labeled); day-over-day and MTD columns; drill from every figure. AC: DOC figures = fixture ledger/feeds exactly; source labels correct; stale-feed banner when a source lags [threshold config].

**S120 Statement-Format Financial Packages.** Persona: Controller/CFO. Management financial packages in statement format per entity and consolidated [consolidation = presentation roll-up of entity statements with eliminations sourced from CE-06 pass-2 elimination entries; PUTR — absent that, consolidated view renders WITH a visible "eliminations pending" state, never silently netted]: BS/IS/TB packages using S009 metadata + S104-style profile mappings (governed, blank-until-authored), comparative columns (prior period/year from frozen history), variance columns (computed presentation), export retained. AC: package = ledger byte-exactly; comparative columns = frozen history; eliminations-pending state truthful; cell drill.

**S121 Fixed Ops KPI Pack / S122 Variable Ops KPI Pack.** Persona: GM/department managers/Controller. KPI packs computed server-side from posted + operational-feed data with source labels: S121 — labor gross %, effective labor rate, parts gross, RO counts/aging, WIP, warranty exposure (CE-11 feeds); S122 — front/back gross PVR, F&I product penetration, reserve/chargeback trends, unit days-supply, floorplan expense (CE-12/CE-13 feeds). KPI DEFINITIONS = versioned configuration (formula registry with effective dating — formulas visible on the surface; no black-box numbers). AC: each KPI = registry formula applied to fixture data exactly; formula version displayed; drill to source; missing-feed KPI shows NOT_AVAILABLE truthfully, never zero.

**S123 Compliance Reporting Pack.** Persona: Controller/compliance. Periodic compliance outputs from existing system truth: large-cash-transaction report (CE-09 S057 flags → 8300-style worksheet as EVIDENCE EXPORT, filing not claimed), escheat/unclaimed candidates summary (CE-09/CE-11 queues; module execution is S127/CE-17), sales/use tax summary (CE-10 reconciliation output), 1099 preview linkage (CE-09 S037). Every report: export + retained + hash-stamped + source-labeled; STATUTORY_SOURCE_UNAVAILABLE where a feed is absent. AC: each pack section = its source system byte-exactly; absent-source states truthful; retention per S017.

**S015 Multi-Currency & CTA.** Persona: Controller (multi-entity groups). Scope per accepted R5 story: entity functional-currency designation, foreign-currency transaction capture (rate on transaction date from a RATE SOURCE adapter — `RATE_SOURCE_NOT_CONFIGURED` truthful, manual attested rates valid), period-end remeasurement/translation runs as **preview-approve ceremonies** posting through the engine (translation adjustment/CTA rows in the matrix, blank values), CTA equity tracking, rate-version pinning on every translated figure. **No accounting-policy invention: the remeasure-vs-translate classification per entity is Controller-entered configuration (policy election recorded with authority), not derived.** AC: translation run = approved preview; rate versions pinned; CTA continuity rolls; single-currency tenants see the feature dormant (no noise).

**S016 Signed Statement Snapshots.** Persona: Controller/CFO. Certification ceremony: at PRELIMINARY_CLOSED→FINAL_CLOSED and at statement issuance, an immutable snapshot of the statement package (rendered artifacts + underlying TB + metadata versions + profile versions) is captured, hash-chained, and SIGNED (certifying identity + attestation text + timestamp; dual sign-off where configured — Controller + CFO/dealer principal [SoD]). Any post-signature change = new snapshot version with diff lineage; signatures never edited. AC: snapshot byte-stable and hash-verifiable later; re-render of a signed period matches its snapshot or raises integrity alert; dual-sign flow enforced when configured.

**S017 WORM Archive & PII Crypto-Shredding.** Persona: Admin/compliance + system. Write-once retention store for close evidence, snapshots, exports, audit extracts: WORM semantics at the application layer (immutable objects, retention-hold flags, deletion refusal while held) over object storage [storage-level WORM/compliance-mode = deployment configuration, truthfully reported as configured-or-not]. **Retention periods = tenant configuration per record class (statutory values not invented; empty schedule ⇒ indefinite hold + visibility flag).** PII crypto-shredding: personal-data fields in archived objects encrypted per-subject; DSAR-driven erasure (execution workflow = S126/CE-17) destroys the subject key rendering PII unreadable while preserving financial integrity (amounts/journal structure retained; identity fields shredded) — shred ceremony with dual authorization + evidence. AC: held object deletion refused; retention-expiry release only via governed job with audit; key-shred renders fixture PII unreadable while journals still foot; shred is evidenced and irreversible-by-design (declared, ceremonied).
