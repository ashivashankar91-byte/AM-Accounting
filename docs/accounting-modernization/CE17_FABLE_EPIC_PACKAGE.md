## OBJECTIVE & THE EARNED-AUTOMATION LAW
Automation in this program is **earned, bounded, and evidenced**: every automated capability shadows a proven manual twin (built in CE-07..CE-15), starts in observation, recommends before it prepares, prepares before it executes, and executes only inside deterministic policy gates with full lineage. **Automation never silently performs an irreversible financial action.** Where a deterministic rule suffices, no ML model is built or claimed; where a statistical model is genuinely used, it is versioned, evidenced, and never autonomous beyond its granted authority. No autonomous-AI claim is made anywhere unless implemented and certifiable.

## AUTHORITY & POLICY FRAMEWORK (governs all 14 stories; server-enforced)
**Authority levels** per automation capability × tenant × entity: `OBSERVE_ONLY → RECOMMEND → PREPARE_DRAFT → EXECUTE_WITH_APPROVAL → AUTO_EXECUTE_WITHIN_POLICY → SUSPENDED`. Grants are governed configuration: author≠activator SoD (standing D-S023-28 pattern), effective-dated, versioned, audited; default for every new capability = OBSERVE_ONLY; promotion requires recorded baseline evidence from the manual twin (the earned gate). **Deterministic policy gates** evaluated server-side before ANY automated mutation: monetary limit per action/period · confidence threshold (where scoring exists) · exception-category allowlist · closed-period refusal (S008 truth) · missing-mapping refusal (standing rule) · statutory-unsupported refusal · cross-entity refusal unless expressly granted · high-risk transaction classes (config) → forced APPROVAL_REQUIRED · irreversible-action classes → never AUTO (ceiling EXECUTE_WITH_APPROVAL) · repeated-failure circuit breaker (N failures ⇒ capability SUSPENDED + alert). **Truthful states:** NOT_CONFIGURED · OBSERVATION_ONLY · RECOMMENDATION_READY · APPROVAL_REQUIRED · EXECUTION_PENDING · EXECUTED · FAILED_CLOSED · SUSPENDED · MODEL_OR_RULE_UNAVAILABLE. **Evidence per automated action (immutable):** source evidence refs · recommendation/decision evidence (rule hits or model output) · rule/model version · confidence where applicable · tenant/LE · automation identity · approving identity where required · idempotency key · resulting source transaction + posting execution + journal + schedule/reconciliation effects · correction/reversal lineage. All financial effects ride the governed path (event → CE-07 → journal → JOURNAL_ENTRY_POSTED); automation NEVER writes GL/schedules directly (static check). Standing discipline (tenancy, RLS, additive migrations, blank matrix rows, unified-shell UI, server-side computation, standard states) incorporated by reference.

## STORY CONTRACTS (each: objective · persona · trigger · workflow · authority ceiling · accounting effect · negative paths · ACs)

**S022 Rule Simulation Sandbox (R6 — first, it is the safety tool).** Persona: Accounting/Controller. Extends the approved S023 simulate: sandbox workspaces to run event SETS (historical replays, synthetic scenarios, draft pack versions) producing proposed-journal sets + diff-vs-actual reports — **zero posting, zero schedule mutation, zero operational writes, ever** (structural guarantee, tested). AC: sandbox run over fixture history = deterministic blueprint set; diff report exact; no mutation path exists (static + runtime proof); sandbox evidence exportable as baseline records.

**S040 OCR/EDI Invoice Ingestion.** Persona: AP clerk. Manual twin: S039. Ingest channels (document upload/OCR extraction adapter, EDI feed adapter — truthful NOT_CONFIGURED; extraction vendor = adapter boundary, fixtures for cert) → extracted fields land as **DRAFT invoices with field-level confidence + source-image linkage**, never auto-submitted below authority. RECOMMEND: dedupe/vendor-match/coding suggestions from deterministic rules first (vendor history, PO linkage); PREPARE_DRAFT: populated S039 draft awaiting clerk; EXECUTE_WITH_APPROVAL: clerk one-click accept per invoice; AUTO within policy: only clean-extraction + in-limit + known-vendor + non-exception invoices, each still fully evidenced. Accounting effect: none until the S039 flow posts normally. Negative: low-confidence field forces review; duplicate suspect forces review; limit/closed-period/missing-mapping gates refuse. AC: extraction evidence retained (image↔field trace); authority ladder enforced server-side; auto-accepted fixture set posts identically to manual entry; circuit breaker on repeated extraction failures.

**S058 Lockbox AI Remittance Matching.** Persona: AR clerk. Manual twin: S052 application + S101A-style matching. Lockbox file adapter (truthful states) → remittance lines scored against open AR items (deterministic keys first: exact amount+applyNumber/reference; scoring only for residual ambiguity — model versioned where used) → RECOMMEND matches w/ evidence; EXECUTE_WITH_APPROVAL batch-accept; AUTO within policy for exact-key matches only. Unmatched → exception routing (investigation worklist). Accounting: applications post via the standard receipt path. AC: exact-key auto set = deterministic; scored suggestions never auto-apply; every application lineaged to remittance line; duplicate lockbox file idempotent.

**S073 LIFO Overlay.** Persona: Controller + tax preparer. **S091B Experience-Rated Chargeback Model.** Persona: Controller/F&I director. Manual twin: S091 flat-%. Reserve posting continues through S091's existing preview-approve. AC: model output reproducible per version on fixture history; adoption ceremony required (no silent rate change); side-by-side flat-vs-experience comparison view; drift monitor flags cohort shift (alert only).

**S128 SOX Evidence Automation.** Persona: Controller/internal audit.
